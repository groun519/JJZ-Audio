# JJZero Audio 0.3.3 사전 마감표

> 이 문서는 0.3.3 안정화 릴리스의 범위와 검증 순서를 관리합니다. 사용자용 패치노트가 아닙니다.

## 릴리스 원칙

- 기준 공개 버전: `0.3.2` (`v0.3.2`, `5b0a007`)
- 목표 버전: `0.3.3`
- 성격: 기능 동결형 안정화 릴리스
- 새 기능과 디자인 개편은 받지 않습니다.
- 충돌, 작업 실패, 데이터 손실, 설치·업데이트 실패, 핵심 재생 문제만 차단 오류로 다룹니다.
- 구현 완료만으로 범위를 확정하지 않습니다. 자동 테스트와 실제 앱 검증을 모두 통과한 변경만 포함합니다.
- 다른 작업이 끝나기 전에는 앱 버전, Windows 버전 정보, README의 공개 버전을 올리지 않습니다.

현재 작업 트리에서 진행 중인 변환, 모델 분석, 학습 재료 처리, 진단 표시 변경은 아직 확정 범위가 아닙니다. 각 변경은 관련 테스트와 실제 작업 검증이 끝난 뒤 이 표로 이동합니다.

## 사전 검증 기록

2026-08-14 기준으로 기능 동결 전에 실행할 수 있는 검증은 다음과 같이 통과했습니다.

- Python 전체 컴파일 통과
- 전체 `unittest` 1,094개 통과
- `git diff --check` 통과
- Git에 설치 파일, 런타임 압축 파일, 모델, 음원, 영상, 캐시가 추적되지 않음을 확인
- 기존 0.3.2 애플리케이션 배포 폴더 검증 통과
- 기존 0.3.2 컴포넌트 릴리스와 `latest.json` 검증 통과
- Inno Setup 6 컴파일러 탐지 확인
- README, CHANGELOG, 릴리스 문서를 포함한 Markdown 파일의 UTF-8 유효성 확인

이 결과는 현재 작업 트리의 중간 기준선입니다. 다른 작업이 병합된 뒤 전체 테스트와 배포 검증을 다시 실행해야 하며, 이 기록만으로 0.3.3 배포 가능 상태를 선언하지 않습니다.

## 기능 동결 조건

1. 병렬 작업을 모두 끝내고 기능별 커밋 경계를 확정합니다.
2. 미추적 소스와 테스트가 누락되지 않았는지 확인합니다.
3. 생성 파일, 로컬 미디어, 모델, 런타임, 캐시가 Git 변경에 포함되지 않았는지 확인합니다.
4. `git diff --check`가 통과해야 합니다.
5. `CHANGELOG.md`의 `Unreleased`에는 검증이 끝난 사용자 변경만 기록합니다.
6. 연구 기록은 제품 코드와 분리하고, 실행 경로에서 사용하지 않는 실험 코드는 포함하지 않습니다.

## 자동 검증 게이트

프로젝트 루트에서 다음 순서로 실행합니다.

```powershell
.\.venv\Scripts\python.exe -m compileall -q src scripts tests
.\.venv\Scripts\python.exe -m unittest discover -s tests -p "test_*.py"
git diff --check
```

합격 조건은 다음과 같습니다.

- 컴파일 오류 `0건`
- 전체 테스트 실패·오류 `0건`
- 테스트 중 예상하지 않은 최상위 Qt 창 생성 `0건`
- 테스트 종료 후 남은 Python, FFmpeg, RVC 작업 프로세스 `0건`
- 공백 오류와 충돌 표식 `0건`

## 하드웨어 검증

- NVIDIA CUDA: 분리, RVC 변환, 모델 학습
- AMD DirectML: 분리와 RVC 변환, CPU 학습 안내
- AMD ROCm Windows 실험 경로: 설치 가능 여부와 실패 진단
- CPU 전용: 지원 작업이 CPU로 실행되고 GPU 전용 작업은 시작 전에 명확히 차단됨

하드웨어를 직접 확보하지 못한 경로는 지원 완료로 표기하지 않습니다. 대신 진단 로그가 GPU, 드라이버, 런타임 프로필, 폴백 선택과 실패 명령을 구분해서 남기는지 확인합니다.

## 설치·업데이트·데이터 보존

로컬 검증 기준 자료는 준비되어 있습니다.

- `release/JJZero-Audio-0.3.2-Setup.exe`
- `release/v0.3.2-latest.json`
- 보존 매니페스트 SHA-256: `EBDF210B940ECD9B1A76799D5DF675847402309F8196E6767CF628B220F3F607`

1. 0.3.3 새 설치를 임시 경로에서 검증합니다.
2. 공개 0.3.2 설치 프로그램으로 기준 설치 후 0.3.3 업데이트 설치를 검증합니다.
3. 업데이트 전후 곡, 분리 결과, 변환 결과, 모델, 외부 연결 모델, Studio 세션, 내보낸 파일의 해시와 목록을 비교합니다.
4. 저장 위치가 C 드라이브가 아닌 경우에도 Data, Output, Runtime, Cache가 설정된 루트를 유지하는지 확인합니다.
5. 제거 프로그램이 앱과 관리 런타임·캐시는 제거하고 사용자 Data, Output, 모델 가중치와 학습 로그는 보존하는지 확인합니다.

설치 프로그램 검증은 다음 도구를 사용합니다.

```powershell
powershell -ExecutionPolicy Bypass -File scripts\verify_installer.ps1 `
  -InstallerPath release\JJZero-Audio-0.3.3-Setup.exe `
  -PreviousInstallerPath release\JJZero-Audio-0.3.2-Setup.exe

powershell -ExecutionPolicy Bypass -File scripts\verify_uninstaller_storage.ps1 `
  -InstallerPath release\JJZero-Audio-0.3.3-Setup.exe
```

## 런타임 패키징 판정

현재 감사 시점의 런타임 버전은 다음과 같습니다.

- AI 런타임: `4`
- RVC CUDA 11.8: `2`
- RVC CUDA 12.8: `1`
- RVC DirectML: `2`
- RVC ROCm Windows: `2`

최종 기능 동결 뒤 `v0.3.2`와 비교해 런타임 소스, 의존성, 모델 자산, 프로필 버전이 모두 같으면 0.3.2 런타임을 재사용하는 앱 전용 릴리스로 빌드합니다. 하나라도 바뀌었다면 해당 구성요소 버전을 올리고 전체 런타임 패키지를 다시 만듭니다. 코드가 바뀌었는데 구성요소 버전이 그대로인 상태는 허용하지 않습니다.

앱 전용 후보 빌드 예시는 다음과 같습니다.

```powershell
.\scripts\build_release.ps1 -SkipRuntimeBuild -RequireCodeSigning `
  -RuntimeReleaseTag v0.3.2 `
  -RuntimeManifestPath release\v0.3.2-latest.json
```

## 버전 및 문서 마감

1. `CHANGELOG.md`의 `Unreleased`를 Added, Changed, Fixed, Quality로 분류합니다.
2. 사용자용 `docs/releases/0.3.3.md`를 작성합니다.
3. `src/jang_app/version.py`를 `0.3.3`으로 변경합니다.
4. `scripts/release_version.py write-windows-info`로 Windows 버전 정보를 생성합니다.
5. 한국어·영문 README의 공개 버전과 패치노트 링크를 `0.3.3`으로 변경합니다.
6. 전체 테스트와 앱 빌드를 다시 실행합니다.
7. 릴리스 커밋 뒤 깨끗한 작업 트리에서 설치 프로그램과 업데이트 매니페스트를 만듭니다.

## 최종 배포 게이트

```powershell
powershell -ExecutionPolicy Bypass -File scripts\verify_release_readiness.ps1
```

공개 배포는 다음 조건을 모두 만족할 때만 진행합니다.

- 배포 파일과 `latest.json`의 버전, 크기, SHA-256이 일치함
- 필수 RVC 프로필이 매니페스트에 존재함
- 실행 파일과 설치 프로그램의 Authenticode 서명이 유효함
- 0.3.2 앱에서 0.3.3 업데이트가 감지되고 설치됨
- 새 설치와 업데이트 설치에서 사용자 데이터 손실이 없음
- 설치 후 처음 실행부터 핵심 스모크 테스트가 통과함
- Git 작업 트리가 깨끗하고 릴리스 커밋과 태그가 같은 소스를 가리킴

배포 후 GitHub Releases에서 설치 파일과 패치노트를 직접 열고, 업데이트 확인과 실제 다운로드를 한 번 더 검증합니다.
