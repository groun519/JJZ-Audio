# JJZero Audio 0.3.12 온보딩 · 도움말 · 문제 신고 계획

> 상태: 목업 / 구현 전 계획 문서  
> 대상 브랜치: `mockup/jjz-ui-plan`  
> 기준 버전: `0.3.11` 완료 이후  
> 목표 버전: `0.3.12`  
> 상위 마일스톤: 배포 준비가 모두 끝난 뒤 `0.4` 승격

---

# 1. 0.3.12의 역할

0.3.12는 **신규 사용자가 JJZero Audio를 혼자 이해하고, 막혔을 때 스스로 도움을 받고, 문제가 발생하면 한 번의 전송으로 신고할 수 있게 만드는 버전**이다.

핵심 범위는 세 가지다.

1. 페이지별 튜토리얼
2. 상시 접근 가능한 도움말
3. 구조화된 문제 신고 / 버그 리포트

0.3.11이 설치, 업데이트, 제거, 저장소 안정성을 책임지는 버전이라면 0.3.12는 **사용성과 지원 경로를 닫는 버전**이다.

---

# 2. 0.4와의 관계

0.3.12 완료만으로 바로 0.4로 올리지는 않는다.

0.4 승격 조건:

- 0.3.11 배포 안정화 완료
- 0.3.12 온보딩 / 도움말 / 문제 신고 완료
- 신규 사용자 기준 전체 사용 흐름 검증
- 최종 배포 회귀 테스트 완료

최종 목표:

```text
설치 가능
+ 제거 가능
+ 처음 보는 사용자도 사용 가능
+ 문제가 생기면 신고 가능
= 0.4
```

# 3. 튜토리얼 기본 방향

## 3.1 전체 강제 튜토리얼은 사용하지 않는다

JJZero Audio는 기능이 페이지별로 분리되어 있다.

현재 주요 페이지:

```text
Library
Models
Separation
Conversion
Studio
Export
```

사용자마다 필요한 기능이 다르므로, 하나의 긴 "첫 작품 완주" 튜토리얼을 강제로 진행시키지 않는다.

대신 **페이지별 튜토리얼**을 기본 구조로 사용한다.

---

# 4. 최초 전체 Workflow Overview

첫 실행 설정이 끝나고 메인 UI에 진입한 신규 사용자에게 전체 작업 흐름을 한 번만 간단히 안내한다.

예시:

```text
JJZero Audio에 오신 것을 환영합니다.

기본 작업 흐름

1. Library에서 곡을 추가합니다.
2. Separation에서 보컬을 분리합니다.
3. Conversion에서 RVC 모델로 변환합니다.
4. Studio에서 편집합니다.
5. Export에서 결과물을 저장합니다.

[시작하기]    [건너뛰기]
```

목적은 기능 설명이 아니라 **전체 지도를 보여주는 것**이다.

세부 사용법은 각 페이지 튜토리얼이 담당한다.

---

# 5. 페이지별 튜토리얼

각 페이지에 처음 진입했을 때 아직 해당 페이지 튜토리얼을 본 적이 없다면 안내를 제공한다.

예시:

```text
Separation 튜토리얼

이 페이지에서 보컬과 반주를 분리하고
결과를 비교할 수 있습니다.

[튜토리얼 시작]    [스킵]
```

## 상태

각 페이지는 독립적으로 다음 상태를 가진다.

```text
unseen
completed
skipped
```

예:

```text
Library     completed
Models      skipped
Separation  completed
Conversion  unseen
Studio      unseen
Export      unseen
```

규칙:

- `unseen`: 최초 진입 시 안내 가능
- `completed`: 자동으로 다시 띄우지 않음
- `skipped`: 자동으로 다시 띄우지 않음
- `completed`와 `skipped` 모두 도움말에서 언제든 다시 실행 가능

**스킵은 영구 포기가 아니다.**

---

# 6. 튜토리얼 UX

튜토리얼은 별도 슬라이드쇼보다 **실제 UI 위에 Spotlight / Callout을 표시하는 방식**을 우선한다.

예:

```text
┌───────────────────────────────────────┐
│ Library                               │
│                                       │
│              ┌──────────────┐         │
│              │ + Add Song   │ ← 강조  │
│              └──────────────┘         │
│                                       │
│  "작업할 곡을 먼저 추가하세요."       │
│                                       │
│       [이전] [스킵] [다음]            │
└───────────────────────────────────────┘
```

원칙:

- 실제 컨트롤을 강조
- 한 단계에 한 개념만 설명
- 설명은 짧게 유지
- 튜토리얼 때문에 실제 기능을 가로막지 않음
- 사용자가 언제든 스킵 가능
- 화면 크기 변경에 대응
- 강조 대상이 존재하지 않으면 안전하게 다음 단계 또는 도움말로 전환

---

# 7. 페이지별 튜토리얼 범위

## 7.1 Library

설명 대상:

- 곡 추가
- 작업곡 선택
- 곡 상세
- Quick Create
- 결과 / 자산 확인

Quick Create는 "기본 사용 흐름을 압축하는 빠른 기능"으로 설명한다.

## 7.2 Models

설명 대상:

- 모델 가져오기
- 관리 모델과 연결 모델 개념
- 모델 학습 진입
- 모델 평가
- Google Drive 공유 / 가져오기

모델 학습 전체 과정을 최초 튜토리얼에서 모두 설명하지 않는다.

## 7.3 Separation

설명 대상:

- Fast
- Precision
- Custom
- 분리 결과 비교
- 결과 선택
- Conversion으로 이어지는 흐름

처음 사용자에게는 Fast를 기본 추천한다.

## 7.4 Conversion

설명 대상:

- 입력 보컬 선택
- RVC 모델 선택
- Pitch
- 기본 설정
- 결과 비교
- Studio 이동

고급 파라미터를 튜토리얼에서 전부 설명하지 않는다.

## 7.5 Studio

설명 대상:

- Sound Pool
- Timeline
- Clip 선택
- 이동
- Trim / Split
- 기본 Clip 설정
- FX 진입
- Export 연결

Hard Tune, Delay, Doubler 등 개별 고급 효과는 Contextual Help에서 추가 설명한다.

## 7.6 Export

설명 대상:

- Audio / Video
- Preset
- 내보내기 실행
- 결과 관리
- 폴더 열기
- Google Drive 공유

# 8. 상시 도움말

모든 주요 페이지에 `?` 버튼을 둔다.

위치 원칙:

- 페이지 제목 영역 또는 우측 상단
- 페이지마다 같은 위치
- 기능 버튼과 시각적으로 혼동되지 않게 배치

`?` 버튼을 누르면 해당 페이지 전용 도움말을 연다.

예:

```text
Separation 도움말

이 페이지는 무엇을 하는 곳인가

처음이라면
Fast Separation을 권장합니다.

[페이지 튜토리얼 다시 보기]

주요 기능
- Fast
- Precision
- Custom
- 결과 비교
- 결과 선택

문제 해결
- 분리가 시작되지 않음
- Runtime이 준비되지 않음
- GPU 관련 오류

[문제 신고]
```

---

# 9. Contextual Help

페이지 전체 튜토리얼과 별도로 고급 기능에는 필요한 경우 작은 도움말 진입점을 둔다.

예:

- Studio Hard Tune
- Delay
- Doubler
- RVC 학습
- Precision Separation
- 모델 평가
- Runtime / GPU 설정

원칙:

- 모든 버튼에 `?`를 붙이지 않는다.
- 초보자가 의미를 이해하기 어려운 기능만 대상으로 한다.
- 도움말은 실제 기능과 같은 화면에서 짧게 제공한다.

# 11. 문제 신고 진입점

두 가지 진입 경로를 제공한다.

## 11.1 수동 신고

각 페이지의 도움말에서:

```text
[문제 신고]
```

또는 공통 도움말 메뉴에서 진입한다.

## 11.2 오류 발생 직후 신고

실제 오류 UI에 신고 버튼을 제공한다.

예:

```text
RVC 변환에 실패했습니다.

CUDA out of memory

[다시 시도]  [자세히 보기]  [문제 신고]
```

이 경로에서는 오류 컨텍스트를 자동으로 신고 화면에 전달한다.

# 16. 신고 전송 기본 아키텍처

## 16.1 전용 Cloudflare 계정

JJZero Audio 문제 신고용 Cloudflare 계정을 별도로 운영한다.

목적:

- JJZ 신고용 무료 Worker 한도를 다른 프로젝트와 분리
- GitHub 인증 Secret 격리
- JJZ 운영 인프라 분리
- 실수로 다른 Worker가 JJZ 한도를 소비하지 않게 함

기본 플랜은 **Workers Free**로 유지한다.

유료 플랜 자동 전환을 전제로 하지 않는다.

## 16.2 Primary 경로

```text
JJZero Audio
    ↓
HTTPS POST
    ↓
JJZ 전용 Cloudflare Worker
    ↓
GitHub REST API
    ↓
JJZ-Reports GitHub Issues
```

개발자는 최종적으로 **GitHub Issues만 확인**한다.

Cloudflare는 DB가 아니다.

역할:

- 요청 검증
- Rate Limit
- Payload 크기 제한
- Report ID 처리
- GitHub 인증
- GitHub Issue 생성
- 결과 반환

# 18. GitHub 인증

GitHub Personal Access Token 또는 이에 준하는 인증 정보는 JJZero Audio 클라이언트에 포함하지 않는다.

저장 위치:

```text
Cloudflare Worker Secret
```

JJZ 실행 파일에는 GitHub 쓰기 권한을 가진 Secret이 존재하지 않아야 한다.

---

# 19. Report ID

신고 버튼을 누르는 순간 JJZero Audio가 로컬에서 Report ID를 생성한다.

예:

```text
JR-20260830-A81F92
```

Report ID는 다음 모든 위치에서 동일하게 사용한다.

- Local Outbox
- Cloudflare 요청
- GitHub Issue
- 사용자 접수 결과

목적:

- 중복 신고 식별
- 전송 재시도
- 사용자 문의 식별
- 응답 유실 시 중복 Issue 방지

# 20. 정상 신고 UX

```text
[보내기]
    ↓
로컬 Outbox에 먼저 저장
    ↓
Cloudflare Worker 전송
    ↓
GitHub Issue 생성
    ↓
성공 응답
    ↓
Local Outbox 항목 제거
    ↓
접수 완료
```

사용자 화면:

```text
신고가 접수되었습니다.

Report ID
JR-20260830-A81F92

[닫기]
```

정상적인 사용자는 서버 구조를 알 필요가 없다.

---

# 21. Local Outbox

신고 전송 전 로컬에 임시 저장한다.

예:

```text
%LOCALAPPDATA%\JJZero Audio\reports\outbox\
    JR-20260830-A81F92.json
```

목적:

- 앱 종료
- 네트워크 단절
- 응답 유실
- Cloudflare 장애

상황에서도 신고 내용을 잃지 않게 한다.

Outbox에는 정제된 텍스트 진단 정보만 저장한다.

초기 0.3.12에서는 대형 ZIP이나 원본 미디어를 자동 저장하지 않는다.

---

# 22. 전송 실패 처리

Cloudflare 전송이 실패해도 신고를 조용히 버리지 않는다.

같은 세션에서 제한된 자동 재시도를 수행한다.

예:

```text
즉시 재시도
→ 짧은 지연
→ 다시 시도
```

계속 실패하면:

```text
자동 신고를 현재 전송하지 못했습니다.

신고 내용은 이 PC에 안전하게 저장되었습니다.

[다시 시도]
[GitHub에서 직접 제출]
[리포트 복사]
```

사용자가 앱을 다시 실행하면 Outbox의 미전송 신고를 다시 전송한다.

# 23. 최종 수동 Fallback

외부 서비스 장애나 인터넷 단절 등으로 자동 제출이 불가능한 경우만 제공한다.

## GitHub에서 직접 제출

- 브라우저에서 Issue 작성 화면을 연다.
- 제목과 본문을 자동으로 준비한다.
- GitHub 로그인이 필요한 비상 경로다.

## 리포트 복사

- 정제된 신고 내용을 클립보드에 복사한다.
- 사용자가 원하는 채널로 전달할 수 있다.

이 두 방식은 정상 신고 경로가 아니다.

---

# 24. Cloudflare 무료 운영 원칙

JJZero Audio 신고 시스템은 **무료 운영**을 전제로 한다.

원칙:

- JJZ 전용 Cloudflare 계정 사용
- Workers Free 사용
- 유료 플랜을 신고 시스템의 필수 조건으로 두지 않음
- 사용량 증가만으로 자동 과금 구조로 전환하지 않음
- 무료 한도 초과 시 비용을 사용자에게 전가하지 않음
- 사용자 Google / Cloudflare / GitHub 쿼터를 사용하지 않음

신고 시스템의 운영 부담은 JJZero Audio 측 인프라 안에서 해결한다.

---

# 25. 사용자에게 추가 권한을 요구하지 않는다

문제 신고 때문에 다음 권한을 추가로 요청하지 않는다.

- Google Apps Script 실행 권한
- 추가 Google Drive 권한
- GitHub 권한
- Gmail 권한

현재 Google Drive 연결 기능과 문제 신고 시스템은 분리한다.

원칙:

> 사용자 계정 권한과 사용량은 사용자 기능을 위해 사용하고, 개발자 운영용 신고 시스템 부담을 사용자에게 전가하지 않는다.

---

# 26. Worker 기본 방어

Worker는 공개 엔드포인트이므로 최소한의 방어를 둔다.

- POST만 허용
- 최대 Payload 크기 제한
- 허용된 Content-Type 확인
- 필수 필드 검증
- 문제 유형 allowlist
- 문자열 최대 길이 제한
- 비정상 중첩 데이터 거부
- Report ID 형식 검증
- 중복 Report ID 방지
- 과도한 반복 요청 제한
- GitHub API 오류를 그대로 사용자에게 노출하지 않음

초기 구현에서 불필요한 복잡한 사용자 식별 체계를 만들지는 않는다.

---

# 27. 자동 오류 신고는 하지 않는다

사용자 동의 없이 오류를 자동 전송하지 않는다.

오류가 발생하면:

```text
[문제 신고]
```

를 제공하고 사용자가 직접 전송을 선택해야 한다.

단, 신고 화면을 열었을 때 필요한 오류 정보는 자동으로 채운다.

---

# 28. 신고 첨부물 정책

0.3.12 초기 버전에서는 다음을 자동 업로드하지 않는다.

- 음원
- 영상
- RVC 모델
- 전체 Diagnostic ZIP
- 대용량 로그
- 프로젝트 파일

필요하면 이후 버전에서 별도 동의 기반 첨부 시스템을 검토한다.

초기 목표는 **작고 구조화된 텍스트 리포트**다.

---

# 29. 도움말과 문제 신고 연결

각 페이지 도움말 하단에 다음 항목을 둔다.

```text
문제가 해결되지 않았나요?

[문제 신고]
```

오류 신고 시 현재 도움말 페이지의 카테고리를 신고 유형에 반영한다.

예:

```text
Studio 도움말
→ 문제 신고
→ 기본 Category: Studio
```

---

# 30. 구현 예상 위치

정확한 파일 구조는 구현 직전 저장소 상태를 다시 확인한 뒤 확정한다.

예상 신규 영역:

```text
src/jang_app/qt_app/help/
src/jang_app/qt_app/report/
src/jang_app/services/tutorial_state.py
src/jang_app/services/problem_report.py
src/jang_app/services/report_outbox.py
```

Cloudflare Worker는 앱 코드와 분리된 배포 단위로 관리한다.

예:

```text
infrastructure/report-worker/
```

단, 프로젝트 구조 원칙상 별도 저장소가 더 적절하다고 판단되면 JJZ 소스 저장소에 억지로 넣지 않는다.
