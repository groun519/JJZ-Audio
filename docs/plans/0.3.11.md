# JJZero Audio 0.3.11 배포 전 완전 안정화 계획

> 상태: Step 1-4 완료, Step 5 이후 구현 전
> 대상 브랜치: `main`
> 기준 버전: `0.3.10` + Complete Removal 엔진 기준선 (`3f85ca0`)
> 목표 버전: `0.3.11`
> 목적: 공개 배포 전에 설치, 업데이트, 저장소, 계정 자격 증명, 제거, 복구 흐름을 끝까지 검증 가능한 상태로 만든다.

---

## 1. 0.3.11의 역할

0.3.11은 기능 확장 버전이 아니라 **배포 안정화 버전**이다.

이 버전에서 해결해야 하는 핵심 문제는 다음과 같다.

1. 설치된 JJZero Audio가 Windows 시스템 환경을 불필요하게 오염시키지 않는지 검증한다.
2. 일반 제거가 사용자 작업물을 안전하게 보존하면서 재생성 가능한 런타임과 캐시만 제거하는지 보장한다.
3. 사용자가 원할 경우 JJZero Audio가 만든 로컬 상태를 모두 제거할 수 있는 **Complete Removal** 경로를 제공한다.
4. Google Drive 연결에 사용되는 Windows Credential Manager 자격 증명까지 Complete Removal 범위에 포함한다.
5. 설치 → 첫 실행 → 런타임 구성 → 실제 사용 → 업데이트 → 제거의 전체 사이클을 클린 Windows 환경에서 반복 검증할 수 있게 만든다.
6. 제거 및 배포 검증을 수동 확인에만 의존하지 않고 회귀 테스트로 고정한다.

0.3.11에서는 새로운 제작 기능을 추가하지 않는다. 현재 기능을 공개 배포 가능한 상태로 닫는 것이 우선이다.

## 2. 현재 확인된 기준 상태

현재 0.3.10과 이후 배포 안정화 기준선에서 다음 구조가 이미 존재한다.

### 설치

- Inno Setup 스크립트: `packaging/JJZeroAudio.iss`
- 기본 설치 위치: `%LOCALAPPDATA%\Programs\JJZero Audio`
- `PrivilegesRequired=lowest`를 사용하므로 관리자 권한 설치를 기본으로 요구하지 않는다.
- 설치 패키지는 앱 파일을 설치하고, 대형 AI/RVC 런타임은 별도 관리한다.
- 설치 프로그램은 실행 중인 JJZero Audio를 mutex로 확인한다.

### 저장소

기본 저장 구조는 다음 네 영역으로 분리되어 있다.

```text
JJZero storage root/
  Data/
  Output/
  Runtime/
  Cache/
```

부트스트랩 설정, 진단 로그 및 일부 앱 상태는 다음 위치를 사용한다.

```text
%LOCALAPPDATA%\JJZero Audio
```

### 현재 일반 제거

현재 `packaging/JJZeroAudio.iss`는 제거 시 다음 동작을 수행한다.

- JJZero Audio 애플리케이션 파일 제거
- 애플리케이션 소유 `{app}\runtime` 제거
- 기본 관리 Cache `%JJZERO_DATA_ROOT%\cache` 제거
- 애플리케이션 소유 Runtime에 RVC `weights`와 `logs`가 존재하면 제거 전에 별도 보존
- 사용자가 별도 위치로 지정한 외부 Runtime 및 Cache 보존
- `Data` 및 `Output` 보존
- `%LOCALAPPDATA%\JJZero Audio`의 부트스트랩 설정과 로그 보존

RVC 보존 위치:

```text
%LOCALAPPDATA%\JJZero Audio\preserved-runtime\<timestamp>
```

이 계약은 정적 회귀 테스트로 고정되어 있다. `scripts/verify_uninstaller_storage.ps1`은 현재 소스로 빌드한 설치 프로그램을 대상으로 기본 관리 경로 정리와 외부 지정 경로 보존을 각각 실제 검증한다.

### Google Drive 자격 증명

Google Drive OAuth refresh token은 Windows Credential Manager에 다음 Target Name으로 저장된다.

```text
JJZero Audio/Google Drive
```

관련 구현:

- `src/jang_app/services/windows_credentials.py`
- `src/jang_app/services/google_oauth.py`

앱 내부의 Google Drive 연결 해제는 원격 revoke를 시도한 뒤 로컬 Credential Manager 항목과 계정 상태를 제거한다.

현재 일반 Windows 제거만 실행한 경우 해당 Credential Manager 항목은 Complete Reset 관점에서 남을 수 있다.

# 5. 제거 정책

## 5.1 두 가지 제거 모드

0.3.11부터 제거를 명확히 두 종류로 구분한다.

### A. Normal Uninstall

목적:

> 앱을 제거하되 사용자의 작업물과 복구 가능한 개인 데이터를 남긴다.

삭제 대상:

- 설치된 애플리케이션 파일
- 애플리케이션 소유 `{app}\runtime`
- 기본 관리 Cache `%JJZERO_DATA_ROOT%\cache`
- Inno Setup이 생성한 설치 항목 및 바로가기

보존 대상:

- `Data`
- `Output`
- 사용자 생성 RVC `weights`
- 사용자 생성 RVC `logs`
- `preserved-runtime`
- JJZero Audio 부트스트랩 설정
- 진단 로그
- Google Drive Credential Manager 항목
- 사용자가 별도 위치로 지정한 외부 Runtime 및 Cache

0.3.10 이후 안정화한 이 안전한 제거 동작을 기본 모드로 유지한다.

Normal Uninstall은 **재설치 가능성과 사용자 데이터 보존을 우선한다.**

### B. Complete Removal

목적:

> 이 PC에서 JJZero Audio가 생성한 애플리케이션 상태를 완전히 제거한다.

기본 삭제 대상:

- 설치된 애플리케이션 파일
- Runtime
- Cache
- `preserved-runtime`
- `%LOCALAPPDATA%\JJZero Audio`의 JJZero 관리 상태
- 설정
- 진단 로그
- 계정 상태 파일
- 임시 업데이트/다운로드 상태
- Windows Credential Manager의 `JJZero Audio/Google Drive` 항목
- JJZero가 생성한 설치 관련 사용자 레벨 상태

기본 보존 대상:

- `Data`
- `Output`

Complete Removal이라도 **사용자가 만든 곡, 모델, 프로젝트 및 출력물은 별도 확인 없이 삭제하지 않는다.**

# 6. Complete Removal 사용자 흐름

## 6.1 제거 시작 화면

제거 프로그램에서 다음 두 선택지를 제공한다.

```text
○ JJZero Audio 제거
   앱과 재생성 가능한 오디오 엔진/캐시를 제거합니다.
   곡, 모델, 프로젝트, 출력 파일은 유지됩니다.

○ JJZero Audio 완전 제거
   앱, 런타임, 캐시, 설정, 로그, 저장된 계정 정보와
   JJZero가 만든 로컬 상태를 제거합니다.
```

기본 선택은 항상 **Normal Uninstall**이다.

Complete Removal은 사용자가 직접 선택해야 한다.

## 6.2 사용자 작업물 삭제는 별도 단계

Complete Removal을 선택한 경우에도 Data/Output 삭제는 별도 체크박스로 분리한다.

예:

```text
[ ] 저장된 작업물도 함께 삭제

삭제 대상:
D:\JJZero\Data
D:\JJZero\Output

이 작업은 곡, 모델, 프로젝트 및 출력 파일을 영구 삭제합니다.
```

체크하지 않으면 Data/Output은 보존한다.

### 필수 규칙

- 체크박스 기본값은 OFF
- 실제 삭제 경로를 화면에 표시
- 경로를 읽지 못하면 작업물 삭제를 진행하지 않음
- 경로 안전성을 확인하지 못하면 작업물 삭제를 거부
- 저장소 루트 전체를 무조건 지우지 않음
- JJZero가 소유한 것으로 확정된 하위 경로만 제거
- 저장소 루트에 사용자 임의 파일이 남아 있으면 상위 폴더는 유지

# 7. 삭제 안전성 규칙

Complete Removal은 강력한 기능이므로 삭제 대상 검증을 일반 제거보다 더 엄격하게 한다.

## 7.1 절대 삭제하면 안 되는 경로

다음과 같은 후보는 삭제 요청을 거부한다.

- 드라이브 루트
- 사용자 프로필 루트
- `Documents` 전체
- `Downloads` 전체
- `Desktop` 전체
- `%LOCALAPPDATA%` 전체
- `%APPDATA%` 전체
- Windows 디렉터리
- Program Files 전체
- JJZero 저장소 설정에서 확인되지 않은 임의 경로

## 7.2 설정 기반 경로만 신뢰

외부 Runtime/Cache/Data/Output 위치는 현재 저장소 설정 파일을 통해 확인한다.

기준 파일:

```text
%LOCALAPPDATA%\JJZero Audio\settings\storage.json
```

현재 Inno 제거 코드의 `ReadStoragePath()`, `SamePath()`, `PathContains()`, `IsSafeGeneratedRoot()` 계열 안전 검사를 확장해서 사용한다.

## 7.3 실패 시 보수적으로 중단

삭제 가능 여부가 불명확하면 **삭제하지 않는 방향으로 실패**한다.

예:

- storage.json 손상
- 경로 파싱 실패
- 외장 드라이브 연결 해제
- 권한 오류
- 파일 잠금
- 경로가 예상보다 상위 디렉터리를 가리킴

이 경우 제거 프로그램은 삭제하지 못한 항목과 위치를 사용자에게 알려야 한다.

# 8. RVC 개인 데이터 처리

현재 Normal Uninstall은 애플리케이션 소유 Runtime 제거 전에 다음 사용자 데이터를 보존한다.

```text
Runtime/rvc/weights
Runtime/rvc/logs
```

이 동작은 유지한다.

## Normal Uninstall

- `weights`, `logs`를 `preserved-runtime/<timestamp>`로 이동
- 애플리케이션 소유 Runtime 제거
- 보존 위치를 사용자에게 안내

## Complete Removal

Complete Removal에서는 사용자가 "작업물 삭제"를 선택하지 않아도 `preserved-runtime`은 **JJZero 로컬 상태 제거 범위**에 포함한다.

단, Complete Removal 화면에서 개인 RVC 데이터가 함께 제거된다는 사실을 명확히 표시한다.

작업물 보존 정책과 충돌하지 않도록 향후 구현 시 다음을 확정한다.

- 관리 모델로 이미 Data 영역에 들어간 RVC 모델은 Data 정책을 따른다.
- Runtime 내부 학습 중간물과 preserved-runtime은 Complete Removal 정책을 따른다.

# 9. Google Drive Credential Manager 정리

## 9.1 제거 대상

Complete Removal에서 다음 정확한 Target만 제거한다.

```text
JJZero Audio/Google Drive
```

다른 Windows Credential Manager 항목은 검색하거나 삭제하지 않는다.

## 9.2 원격 revoke와 로컬 삭제 구분

앱 내부의 "Google Drive 연결 해제"는 Google revoke API를 호출할 수 있다.

반면 Windows 제거 프로그램은 네트워크 상태나 OAuth 서비스 가용성에 의존해서는 안 된다.

따라서 Complete Removal의 필수 조건은:

1. 로컬 Credential Manager 항목 제거
2. 로컬 Google 계정 상태 제거

원격 Google 토큰 revoke는 앱에서 정상적으로 연결 해제했을 때 수행하는 경로로 유지한다.

제거 프로그램이 원격 revoke 실패 때문에 Complete Removal 전체를 실패 처리하지 않는다.

## 9.3 검증

Complete Removal 회귀 테스트는 테스트용 Credential Manager 항목을 생성하고 제거 후 해당 Target이 존재하지 않는지 확인해야 한다.

실제 사용자의 다른 자격 증명은 건드리지 않는다.

# 10. Windows 시스템 비침투 원칙

0.3.11에서 현재 배포 방식이 시스템에 불필요한 전역 변경을 만들지 않는지 명시적으로 검증한다.

JJZero Audio는 다음 항목을 설치 과정에서 수정하지 않는 것을 원칙으로 한다.

- 시스템 Python
- 사용자 전역 Python
- 시스템 CUDA
- 시스템 ROCm
- GPU 드라이버
- 시스템 PATH
- 사용자 PATH
- 전역 PYTHONPATH
- 시스템 환경 변수
- Windows 서비스
- 시작 프로그램
- 파일 연결
- 다른 프로그램의 설정
- 시스템 전역 패키지 관리자 상태

JJZero 전용 Python 및 AI 런타임은 관리 Runtime 내부에서만 존재해야 한다.

Inno Setup의 일반 설치 등록, 바로가기 및 JJZero 전용 사용자 레벨 파일은 허용한다.

# 12. 자동 회귀 테스트 계획

## 12.1 기존 제거 테스트 확장

현재:

```text
scripts/verify_uninstaller_storage.ps1
```

현재 검증 범위:

- 애플리케이션 소유 Runtime 제거

- Data/Output 및 부트스트랩 설정/진단 로그 보존
- 애플리케이션 소유 Runtime의 RVC weights/logs 별도 보존

0.3.11에서 다음 두 모드로 확장한다.

```text
Normal
Complete
```

또는 테스트 책임이 과도해질 경우 다음처럼 분리한다.

```text
scripts/verify_uninstaller_storage.ps1
scripts/verify_complete_uninstall.ps1
```

구현 시 한 파일이 지나치게 복잡해지지 않는 쪽을 선택한다.

# 14. 클린 Windows E2E 검증

자동 테스트만으로 배포 완료를 판정하지 않는다.

최종 0.3.11 후보 설치 프로그램은 깨끗한 Windows 사용자 환경 또는 VM 스냅샷에서 실제로 검증한다.

## Phase A - 기준 상태 기록

설치 전 다음 상태를 기록한다.

- `%LOCALAPPDATA%\JJZero Audio` 존재 여부
- JJZero 설치 디렉터리 존재 여부
- 테스트 저장소 루트 상태
- Windows Credential Manager의 JJZero Target 존재 여부
- 사용자 PATH
- 시스템 PATH
- Python 탐색 결과
- CUDA 관련 전역 환경 상태
- JJZero 관련 레지스트리 항목
- 시작 프로그램 및 서비스 상태

## Phase B - 신규 설치

1. 0.3.11 설치
2. JJZero 실행
3. 외부 저장소 위치 지정
4. 필요한 Runtime 설치
5. 하드웨어 프로필 탐지/활성화
6. 앱 재시작
7. 진단 화면 확인

## Phase C - 실제 사용

최소 한 번 다음 실제 흐름을 수행한다.

1. 곡 등록
2. 보컬 분리
3. RVC 모델 등록 또는 기존 테스트 모델 사용
4. 변환
5. Studio 프로젝트 생성
6. 오디오 출력 생성
7. 가능하면 영상 출력 생성
8. Google Drive 테스트 계정 연결
9. 공유 가능한 테스트 자산 1개 생성

목적은 단순 앱 실행이 아니라 **실제 사용 후 생성되는 모든 상태를 제거 검증에 포함하는 것**이다.

## Phase D - 업데이트

가능하면 다음 경로를 별도 스냅샷에서 검증한다.

```text
0.3.10 설치
→ 실제 데이터 생성
→ 0.3.11 업데이트
→ 기존 프로젝트 정상 로드
```

## Phase E - Normal Uninstall

검증:

- 앱 제거
- 애플리케이션 소유 Runtime 제거
- 기본 관리 Cache 제거
- 외부 지정 Runtime/Cache 유지
- Data 유지
- Output 유지
- 보존 대상 RVC 데이터 유지
- 재설치 후 기존 작업 복구 가능

## Phase F - Complete Removal

새 스냅샷 또는 재설치 환경에서 검증한다.

### 작업물 보존

- JJZero 로컬 상태 제거
- Credential 제거
- Runtime/Cache/preserved-runtime 제거
- Data/Output 유지

### 작업물 포함 완전 제거

- JJZero가 소유한 Data/Output 제거
- LocalAppData 상태 제거
- Credential 제거
- 설치 디렉터리 제거
- Runtime/Cache 제거
- 사용자 임의 파일은 유지

## Phase G - 설치 전/후 비교

Complete Removal 후 Phase A 상태와 비교한다.

허용되는 차이와 JJZero가 남긴 차이를 구분해서 기록한다.

목표:

> JJZero Audio가 만든 항목 중 사용자가 명시적으로 보존하도록 선택한 데이터 외에는 남지 않는다.

# 15. 실패 및 복구 UX

## 제거 중 파일 잠금

- 실행 중 앱이 있으면 제거 시작 금지
- 삭제 실패 파일을 숨기지 않음
- 사용자가 직접 확인할 수 있는 경로 표시

## 외장 저장소 연결 해제

- 접근 불가능한 Data/Output은 삭제했다고 표시하지 않음
- 로컬 앱 상태 제거는 계속 가능
- 제거하지 못한 외부 저장소 경로를 최종 화면에서 안내

## Credential 삭제 실패

- 앱 파일 제거를 롤백하지 않음
- Target 이름과 실패 사실을 표시
- 수동 제거 방법을 문서에 제공
- 회귀 테스트에서는 실패로 판정

## preserved-runtime 이동 실패

Normal Uninstall에서는 현재와 마찬가지로 사용자 데이터를 잃는 것보다 Runtime 제거를 포기하는 방향을 유지한다.

# 20. 0.4 진입 게이트

0.3.11을 끝냈다고 바로 0.4로 올리지 않는다.

0.3.11 이후 다음 단계는 **튜토리얼/온보딩 계획**이다.

그 계획까지 구현하고 신규 사용자가 별도 설명 없이 다음 흐름을 완료할 수 있는 상태를 확인한다.

```text
설치
→ 저장소 설정
→ Runtime 준비
→ 곡 등록
→ 분리
→ RVC 변환
→ Studio
→ Export
```

그 이후 최종 배포 회귀 검증을 한 번 더 수행한다.

최종적으로 다음 세 축이 모두 닫히면 0.4로 승격한다.

```text
기능 안정성
+ 배포/제거 안정성
+ 신규 사용자 온보딩
= 0.4
```

0.4부터는 "개발 중인 로컬 도구"가 아니라 **외부 사용자가 직접 설치하고 사용할 수 있는 제품 상태**를 기준으로 유지한다.
